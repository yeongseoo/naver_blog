# 네이버 블로그 브릿지 (Chrome 확장)

글 생성 웹 서비스의 DB에 쌓인 글을 **정해진 주기마다 가져와 네이버 블로그에 자동 발행**하는 Chrome 확장입니다.
발행은 사용자가 Chrome에 로그인해 둔 네이버 세션으로 하기 때문에 네이버 아이디·비밀번호를 저장하지 않습니다.

```
 [글 생성 웹 서비스 / DB]
        │  ① GET  /pending   발행할 글 가져오기
        ▼
 [Chrome 확장 = 브릿지]  ── ② 네이버 발행 API 호출 (로그인 세션 사용) ──▶ [네이버 블로그]
        │  ③ POST /result    결과(성공/실패, 글 주소) 보고
        ▼
 [글 생성 웹 서비스 / DB]
```

---

## 1. 설치

1. Chrome 주소창에 `chrome://extensions` 입력
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → 이 저장소의 `extension` 폴더 선택
4. 퍼즐 아이콘 → **네이버 블로그 브릿지** 옆 핀(📌)을 눌러 툴바에 고정

> 코드를 수정했다면 `chrome://extensions`에서 확장의 새로고침(↻)을 누르세요.

## 2. 네이버 로그인

Chrome에서 [네이버](https://www.naver.com)에 로그인해 두세요. **로그인 유지**를 체크해 두면 세션이 오래 갑니다.
로그인이 풀리면 발행이 실패하고, 실패 내용이 웹 서비스로 보고됩니다.

## 3. 설정

확장 아이콘 → **설정** (또는 `chrome://extensions` → 확장 세부정보 → 확장 프로그램 옵션)

| 항목 | 설명 | 예시 |
|---|---|---|
| 웹 서비스 API 주소 | 브릿지 API의 기본 주소. 뒤에 `/pending`, `/result`가 붙습니다 | `https://my-service.com/api/naver-bridge` |
| API 토큰 | 웹 서비스가 확인할 비밀 토큰 (`Authorization: Bearer …`) | `sk_live_xxx` |
| 확인 주기(분) | 몇 분마다 새 글을 확인할지 (최소 1분) | `10` |
| 1회 최대 발행 수 | 한 번 확인할 때 최대 몇 개를 발행할지 (1~20) | `1` |
| 기본 발행 방식 | 글에 `mode`가 없을 때 쓸 방식: 발행(공개) / 임시저장 | 발행 |
| 자동 동기화 켜기 | 체크해야 주기 실행이 시작됩니다 | ✅ |

**저장**을 누르면 처음 한 번 "이 사이트에 접근 허용" 권한 창이 뜹니다. **허용**을 눌러야 웹 서비스에 접속할 수 있습니다.
주소는 보안상 `https`만 쓸 수 있습니다. 개발용 `localhost`는 예외입니다.

## 4. 점검 (처음 한 번 권장)

설정 화면 아래쪽 **점검** 영역에서 순서대로 눌러 보세요.

1. **① 웹 서비스 연결 테스트**: 주소와 토큰이 맞는지 확인합니다. `limit=0`으로 호출하기 때문에 글을 가져가지 않습니다.
2. **② 네이버 임시저장 테스트**: 테스트 글을 **임시저장**만 합니다. 성공하면 네이버 글쓰기의 임시저장 목록에서 확인한 뒤 지우세요.

둘 다 성공하면 준비가 끝난 것입니다.

## 5. 사용

- **자동**: 설정한 주기마다 알아서 실행됩니다. 글을 발행할 때 보이지 않는 탭이 잠깐 열렸다가 닫힙니다.
- **수동**: 확장 아이콘 → **지금 동기화**
- **상태 확인**: 확장 아이콘 팝업에서 볼 수 있는 것
  - 마지막 실행 시각과 결과
  - 다음 실행 예정 시각
  - 최근 기록. 성공한 글은 [글 보기] 링크가 붙습니다.

### 꼭 지켜야 할 조건

- **Chrome이 켜져 있어야** 동작합니다. 창이 하나 이상 열려 있어야 하고, 컴퓨터가 절전 상태이면 안 됩니다.
- Chrome이 꺼져 있던 동안 쌓인 글은 다음에 Chrome을 켜고 첫 주기가 돌 때 발행됩니다.

## 6. 웹 서비스가 구현해야 할 API

엔드포인트는 두 개입니다. 모든 요청에는 `Authorization: Bearer <토큰>` 헤더가 붙습니다. 토큰이 틀리면 `401`을 돌려주세요.

### ① `GET {API주소}/pending?limit=N`

발행할 차례가 된 글을 **최대 N개** 돌려줍니다.

- `limit=0`이면 빈 배열을 돌려주세요. 연결 테스트용입니다.
- **돌려준 글은 즉시 `processing`(처리 중)으로 바꿔 주세요.** 같은 글이 두 번 발행되는 것을 막는 핵심입니다.

응답 예시:

```json
{
  "posts": [
    {
      "id": "post_123",
      "title": "글 제목",
      "mode": "publish",
      "scheduledAt": "2026-11-01T09:00:00+09:00",
      "categoryId": 0,
      "blocks": [
        { "type": "heading", "content": "소제목" },
        { "type": "text",    "content": "본문 문단입니다.\n줄바꿈은 새 문단이 됩니다." },
        { "type": "quote",   "content": "인용구" },
        { "type": "divider", "style": "line1" },
        { "type": "text",    "content": "마지막 문단" }
      ]
    }
  ]
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | ✅ | 글 고유 ID. 문자열이나 숫자 |
| `title` | ✅ | 글 제목 |
| `blocks` | ✅ | 본문 블록 배열. 아래 표 참고 |
| `mode` | | `"publish"`(공개 발행) 또는 `"temp"`(임시저장). 없으면 설정의 기본값을 씁니다 |
| `scheduledAt` | | 발행 예정 시각(ISO 문자열 또는 ms). 아직 시각이 안 됐으면 건너뜁니다. 보통은 서버가 시각이 된 글만 주면 됩니다 |
| `categoryId` | | 네이버 블로그 카테고리 번호. 없으면 기본 카테고리 |

**블록 종류**

| type | 필드 | 네이버 에디터에서 |
|---|---|---|
| `text` | `content` | 본문 문단. `\n`마다 문단이 나뉩니다 |
| `heading` | `content` | 소제목 |
| `quote` | `content` | 인용구 |
| `divider` | `style` (선택: `default`, `line1`, `line5`, `line6`, `line7`) | 구분선 |
| `image` | — | ⚠️ **아직 지원하지 않습니다.** 건너뛰고, 결과의 `skippedImages`에 개수를 적어 줍니다 |

### ② `POST {API주소}/result`

글 하나를 처리할 때마다 결과를 보냅니다. 서버는 `2xx`로 응답하세요. 실패 응답이면 확장이 다음 주기에 다시 보냅니다.

```json
{
  "id": "post_123",
  "success": true,
  "mode": "publish",
  "postUrl": "https://blog.naver.com/myblog/223456789012",
  "logNo": "223456789012",
  "blogId": "myblog",
  "skippedImages": 0,
  "error": null,
  "processedAt": "2026-11-01T00:10:12.345Z"
}
```

- `success: true`이면 해당 글을 `done`으로 바꾸고 `postUrl`을 저장하세요.
  - 네이버 응답에서 글 번호를 찾지 못하면 `postUrl`과 `logNo`가 `null`일 수 있습니다.
- `success: false`이면 `failed`로 바꾸고 `error`를 저장하세요. 다시 시도하려면 서버에서 `pending`으로 되돌리면 됩니다.

### 권장 상태 흐름 (DB)

```
pending ──(/pending 으로 가져감)──▶ processing ──(/result success)──▶ done
                                         └────(/result 실패)──────▶ failed ──(재시도 원하면)──▶ pending
```

`processing`에서 오래(예: 30분 이상) 멈춘 글은 Chrome이 중간에 꺼진 경우입니다. 서버가 `failed`로 바꾸거나 직접 확인하세요.
**바로 `pending`으로 되돌리면 실제로는 발행됐는데 또 발행될 수 있습니다.**

### 중복 발행 방지 (확장 쪽)

- 확장은 **발행에 성공한 글 ID를 기억합니다**(최근 300개). 서버가 같은 ID를 다시 줘도 다시 발행하지 않고 결과만 다시 보고합니다.
- 결과 보고가 실패하면(서버 다운 등) 다음 주기에 **보고만** 다시 합니다. 발행은 다시 하지 않습니다.

### 테스트용 서버

규격대로 동작하는 작은 서버가 들어 있습니다. Node.js만 있으면 됩니다.

```bash
node tools/mock-server.js
```

확장 설정에는 아래 값을 넣으세요. 테스트 글 1개가 **임시저장** 모드로 들어 있습니다.

- API 주소: `http://localhost:8787/api/naver-bridge`
- 토큰: `test-token`

## 7. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `네이버 글쓰기 페이지가 열리지 않았습니다` | 네이버 로그인이 풀렸습니다. Chrome에서 다시 로그인하세요 |
| `네이버가 HTML 을 반환했습니다` | 로그인 세션이 만료됐습니다. 다시 로그인하세요 |
| `네이버 거부: …` | 네이버가 발행을 거절했습니다(내용 제한, 발행 횟수 제한 등). 메시지를 확인하세요 |
| `웹 서비스 응답 HTTP 401` | 토큰이 틀렸습니다 |
| `응답에 posts 배열이 없습니다` | `/pending` 응답 형식을 확인하세요. `{ "posts": [...] }` 또는 배열이어야 합니다 |
| `Failed to fetch` | API 주소가 틀렸거나, 설정 저장 때 접근 권한을 거부했습니다. 설정에서 다시 **저장**하세요 |
| 자동 실행이 안 됨 | 설정에서 **자동 동기화 켜기**를 확인하고, Chrome이 켜져 있는지 확인하세요. 팝업의 "다음 실행" 시각도 확인하세요 |

자세한 로그 보는 법: `chrome://extensions` → 네이버 블로그 브릿지 → **서비스 워커** 링크 → Console (`[네이버브릿지 BG]`)

## 8. 알려진 제한

- **이미지 미지원**: 이미지 블록은 건너뜁니다. 네이버 이미지 업로드 연동은 다음 단계입니다.
- **태그 미지원**: 네이버 태그 형식을 아직 확인하지 못해 보내지 않습니다.
- 네이버가 내부 API(`RabbitWrite.naver`)나 문서 형식을 바꾸면 발행이 실패할 수 있습니다. 그때는 `extension/content.js`의 `buildDocumentModel`을 고쳐야 합니다.
- 계정은 Chrome에 로그인된 네이버 계정 하나만 씁니다.
- CAPTCHA·봇 탐지 우회 기능은 없습니다.

```
│   ├── manifest.json   확장 설정 (권한: storage, tabs, alarms)

│   ├── content.js      네이버 글쓰기 페이지 안에서 글을 네이버 문서 형식으로 바꿔 발행 API 호출
│   ├── popup.html/js   상태 · 지금 동기화 · 최근 기록
│   ├── options.html/js 설정 · 연결 점검
│   └── common.css
├── tools/
│   └── mock-server.js  테스트용 API 서버
└── README.md
```
